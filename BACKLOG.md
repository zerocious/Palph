# Backlog — сырые идеи

Этот файл — для **необработанных идей**: то, что ещё не оценено, не размечено по приоритетам и не готово к спринту. Когда идея созревает (есть критерий готовности, понятна цена, выбран приоритет) — переезжает в [TODO.md](TODO.md).

Отличие от секции «Бэклог» в TODO.md:
- **TODO.md → Бэклог** — отложенные задачи с критерием готовности и приоритетом (Must/Should/Could/Won't), просто не в текущем спринте.
- **BACKLOG.md (этот файл)** — идеи без оценки. Сюда сбрасываем мысли, чтобы не потерять, не загромождая TODO.md.

Формат записи (свободный, но желательно):

```
## Заголовок (дата захвата)
**Идея**: суть в 1–2 предложениях
**Зачем**: ценность для пользователя/продукта
**Подход (черновой)**: как могло бы быть реализовано
**Риски**: что может пойти не так
**Стоимость**: примерный объём (код / контент / арт)
**Решение**: defer / yes / no / нужно больше данных
```

## Контекстуализированные («applied») задачи по математике (2026-05-17)

**Идея**: к режиму задач (#14 в TODO.md) добавить задачи-сценарии в формате «ты инженер/менеджер/программист, реши проблему», чтобы математика воспринималась как инструмент, а не самоцель.

**Зачем**:
- Мотивация — «зачем мне это» главная причина дропа в STEM.
- Transfer (перенос знаний): студенты, тренировавшиеся только на абстракции, часто не могут применить ту же математику в новом контексте.
- Дифференциация: Anki / Quizlet / учебники дают абстрактные задачи; applied-ниша свободна.

**Подход (черновой)**:
- **НЕ отдельный режим.** Поле `flavor: "textbook" | "applied"` в JSON задачи (#14).
- Внутри темы: первые 2–3 задачи — чистая математика (закрепить навык), потом applied (показать зачем). Khan Academy делает так же: skill → application.
- Визуальная маркировка: 📐 textbook, 💼 applied.

**Риски**:
- Контент-стоимость ×3–5: хорошая applied-задача требует правдоподобного сценария + проверки что математика реально та же. Плохая хуже абстрактной — добавляет шум.
- Cognitive Load Theory (Sweller): новичкам контекст **мешает**, пока навык не автоматизирован. Важен порядок (abstract → applied), не «два режима на выбор».
- Telegram плохо подходит для длинных сценариев (scroll fatigue) — условия держать короткими.
- Самописные applied-задачи легко скатываются в cringe. Лучше брать у профи в нише или LLM-генерация с человеческим ревью.

**Стоимость**:
- Код: ~0 поверх #14 (поле в JSON + иконка).
- Контент: высокая — нужны интервью с профессионалами или LLM + ревью.
- Арт: 0 (картинка задачи уже в #14).

**Решение**: **defer до v0.8**. Сначала запустить #14 в текущем виде, увидеть как реальные пользователи проходят задачи. Возможно, абстрактных хватит и applied-трек не нужен. Если данные покажут низкий engagement по математике — вернуться к идее.
