# Безопасность

> **Doc sync:** 2026-09-05 · подробные аудиты — в [../audits/](../audits/).

## Поверхность атаки

Бот работает **только на long polling** — публичного HTTP-эндпоинта нет.
Значит, весь недоверенный вход приходит из трёх мест:

1. Текст сообщений и аргументы команд.
2. `callback_data` инлайн-кнопок (пользователь может подделать любую строку).
3. Загружаемые документы (`.txt` со своими задачами).

Плюс два «полудоверенных» источника: файлы учебного контента в репозитории
(`task-NN.json` может ссылаться на произвольное имя картинки) и значения в
БД, попадающие в HTML-подписи.

## Реализованные контроли

### Авторизация

- `is_admin(user_id)` — по in-memory кешу `ADMINS`, наполняемому из БД.
- Права **главного** админа (`/addadmin`, `/rmadmin`, `/listadmins`,
  `/backup`) сверяются с `MAIN_ADMIN_ID` из окружения, а не с таблицей —
  обычный админ не может повысить себя.
- Все callback'и, несущие `user_id` (профиль, карточки, задачи, настройки,
  друзья, питомец), проверяют, что нажимающий = владелец. Иначе — тихий
  отказ.
- Админские команды не показываются обычным пользователям: расширенный
  набор ставится через `BotCommandScopeChat` персонально каждому админу.

### Валидация ввода

- **Аллоулисты вместо санитайза**: `validate_subject_id()` (только
  `SUBJECT_IDS`), ключи разделов квизов, `item_type`/`item_value` питомца
  (`sanitize_pet_asset_keys` схлопывает неизвестное значение к дефолту),
  алиасы таблиц в `/export` (`EXPORTABLE_TABLES`).
- **Лимиты длины**: `FRIEND_QUERY_MAX_LEN = 64`,
  `SUPPORT_MESSAGE_MAX_LEN = TELEGRAM_MAX_MESSAGE_LEN = 4096`,
  `LIST_PREVIEW_MAX_LEN = 80`; `truncate_for_telegram_message()` не даёт
  упереться в лимит Telegram. Явные капы стоят на `/broadcast`, `/reply`,
  пересылке в поддержку и вводе в мастере добавления друга.
- **HTML-экранирование** пользовательских строк (термины и определения
  своих карточек, имя питомца) перед вставкой в HTML-подписи.
- `parse_friend_query()` — чистая функция разбора `@username` / числового id,
  покрыта тестами отдельно от бота.

### SQL

**Значения всегда идут через `?`** — во всём коде нет ни одного места, где
пользовательский ввод попадал бы в текст запроса. F-строки в SQL
встречаются, но только с элементами, которые формирует сам код:

| Место | Что подставляется | Чем безопасно |
|-------|-------------------|---------------|
| `AnalyticsService.export_table_csv` | Имя таблицы | Белый список `EXPORTABLE_TABLES` (20 алиасов), `KeyError` на всё прочее |
| `BackupService._vacuum_into` | Путь файла | Формируется кодом из `BACKUP_DIR`; одинарные кавычки экранируются |
| `UserRepository.delete_user_completely` | Имя таблицы | Итерация по литеральному кортежу из шести имён |
| `PetRepository.purchase_item` / `equip` | Имя колонки | Тернарник `"color" if item_type == "color" else "accessory"` |
| `FlashcardRepository.get_next_card_hash`, `McqProgressRepository.count_mastered`, `TaskProgressRepository.count_mastered`, `_count_*` в `bot.py` | Строка `?,?,?` нужной длины | Генерируется из `len(list)`, сами значения — параметры |

Инъекций через пользовательский ввод нет — подтверждено аудитом
[command-input-security-audit.md](../audits/command-input-security-audit.md).

### Загрузка файлов

Пайплайн `.txt`-импорта своих задач:

1. **До скачивания** — `validate_task_document_metadata()`: имя файла по
   регулярке `^[A-Za-z0-9._ -]{1,128}\.txt$`, MIME из
   `{text/plain, application/octet-stream}`.
2. Скачивание с `asyncio.wait_for(..., timeout=60)`.
3. **После скачивания** — `decode_task_upload()`: размер ≤ 64 КБ,
   `scan_upload_bytes()` (магические префиксы ZIP/ELF/PNG/GIF/PDF/MZ, доля
   NUL-байтов > 5 %), затем строгий UTF-8 декод.
4. Парсинг `user_task_txt.parse_user_tasks_txt()` со своими лимитами:
   ≤ 2000 символов на условие, ≤ 500 на ответ и подсказку, ≤ 20 ответов
   на задачу, ≤ 50 задач на предмет.

Антивируса нет — это осознанно: файл никогда не исполняется, не
распаковывается и не покидает процесс.

### Path traversal

- `safe_subject_dir(root, subject_id)` — резолвит и проверяет
  `relative_to(root)`; используется во **всех** загрузчиках контента.
- `resolve_path_under(dir, filename)` — то же для конкретного файла.
- `safe_task_image_filename(name, task_id)` — из JSON берётся только
  basename и только по маске `*.png`; иначе подставляется
  `<task_id>-solution.png`. Это защита от вредоносного контента в самом
  репозитории (supply chain), а не от пользователя.
- `sanitize_pet_time_period()` — период из БД/кода приводится к
  аллоулисту `{morning, day, evening, night}` до сборки пути к ассету.

### Rate limiting

`UserRateLimiter`: скользящее окно **30 действий / 60 секунд** на
пользователя (in-memory deque). 70 % → вежливое предупреждение (не чаще
раза в 30 с), 100 % → событие тихо отбрасывается. Применяется aiogram-
middleware ко всем Message и CallbackQuery; админы освобождены.

Отдельный, более жёсткий лимитер стоит на пересылке сообщений в поддержку —
**одно сообщение админам в минуту**, без предупреждений:

```python
admin_message_limiter = UserRateLimiter(
    max_actions=1, window_seconds=60, warn_threshold=1.0,
)
```

Что это **не** покрывает: DDoS (нет публичного эндпоинта) и глобальный
лимит Telegram API. После рестарта бакеты пусты — для защиты от абьюза
приемлемо.

### ZIP-бомбы

`validate_zip_member()` (лимит 50 МБ распакованного, коэффициент сжатия
≤ 20, ≤ 500 членов архива) написан заранее — входящие ZIP-архивы бот пока
не принимает.

### Секреты

`BOT_TOKEN` только через окружение; `.env` и `*.key`/`*.pem` в `.gitignore`.
Токен нигде не логируется. `pip-audit --strict` в CI сторожит зависимости.

## Приватность и данные

- **PII не пишется в `bot.log`**: ответы на квизы и текст сообщений там не
  появляются. У обращений в поддержку свой канал — `messages.log`
  (append-only JSONL, одна запись = одна строка; вне git). Там текст
  сообщения есть по назначению — это тикет, который админ должен прочитать;
  запись обрезается до 4096 символов.
- **События почти не содержат текста** — идентификаторы, хеши контента и
  метаданные. Единственное исключение — `pet_renamed`, где сохраняется
  имя питомца (обрезанное до 20 символов); ответы на квизы, сообщения в
  поддержку и прочий пользовательский ввод в `events` не попадают.
- **Хеши контента** (`md5(term)[:8]`) не обратимы к пользовательским данным —
  это хеш учебного материала, а не человека.
- `/delete_account` полностью стирает данные (см.
  [data-model.md](data-model.md) §«Удаление данных пользователя»).
- Privacy opt-out лидерборда — отдельный флаг, не влияющий на начисления.
- Юридическая рамка — [../PRIVACY.md](../PRIVACY.md) (EN) и
  [../PRIVACY.ru.md](../PRIVACY.ru.md) (RU): GDPR + 152-ФЗ.

## Известные ограничения

| Ограничение | Почему приемлемо |
|-------------|------------------|
| Rate limiter не персистится | Перезапуск обнуляет счётчики; атака начнётся заново и снова упрётся в лимит |
| Нет 2FA на админ-командах | Админство привязано к Telegram-аккаунту; компрометация аккаунта = компрометация всего |
| Бэкапы лежат на той же машине | Настоящий DR требует внешнего хранилища — шаблон `scripts/backup_offsite.sh.example` |
| Тесты не гоняются в CI | Прогон обязателен локально перед коммитом; в CI пока только pip-audit |
| Нет шифрования БД на диске | Защита — на уровне доступа к хосту |
