# Рекомендации при разработке

> **Doc sync:** 2026-09-05.

Как добавлять новое, не ломая то, что работает. Архитектурный контекст —
[architecture.md](architecture.md), требования к тестам —
[testing.md](testing.md).

## Принципы, которым следует код

1. **Слои не перепрыгиваем.** Новый SQL — только в `repository.py`.
   Хендлер ходит в репозиторий или сервис, но не в базу. В `bot.py`
   осталось 14 исторических `db.execute` (перечислены в
   [architecture.md](architecture.md)) — это долг, а не пример: касаетесь
   такого участка — выносите запрос в репозиторий.
2. **Логика — в чистых функциях.** Всё, что можно посчитать без БД и без
   `Bot`, выносится в чистую функцию в `services.py` (или
   `plan_service.py`). Это одновременно и тестируемость, и защита от
   случайных зависимостей.
3. **Время приходит параметром.** Любая функция, зависящая от «сейчас»,
   принимает `now_local=None` / `now_utc` и только при `None` лезет в
   часы. Без этого тест на неё будет недетерминированным — см.
   [testing.md](testing.md) §1.
4. **Аллоулист вместо санитайза.** Пришло значение из `callback_data`,
   файла или БД — сверяем со списком известных, а не «чистим».
5. **Аналитика не имеет права ломать продукт.** `event_repo.log()` глотает
   исключения; любой новый вспомогательный слой должен вести себя так же.
6. **Идемпотентность на стороне БД.** Первичные ключи и `INSERT OR IGNORE`
   вместо флажков в памяти: повторный запуск планировщика, ретрай
   Telegram, рестарт процесса не должны выдавать награду дважды.
7. **Сеть — вне локов.** Внутри `async with db.lock` не должно быть ни
   одного `await` в Telegram.
8. **Явные лимиты.** У каждого пользовательского ввода есть максимум:
   длина, количество, размер файла.

## Рецепты

### Новый хендлер

```python
@router.message(kb_in("kb.my_button"))          # ключ i18n, не сырой текст
async def handle_my_button(message: Message, state: FSMContext):
    user_id = message.from_user.id
    locale = await loc(user_id)                  # локаль всегда явно
    ...
    await message.answer(t("my.section.title", locale), reply_markup=...)
```

Чеклист:

- Кнопка сравнивается через `kb_in(...)` / `F.text.in_(all_locale_texts(...))` —
  так хендлер работает на обеих локалях.
- Тексты только через `t(key, locale)`; строковых литералов в ответах нет.
- Для `callback_data` — префикс с двоеточием (`myfeature:action:arg`) и
  **проверка владельца**, если в данных есть `user_id`.
- Значимое действие логируется событием (`event_repo.log`).
- Порядок регистрации важен: специфичные фильтры выше общих,
  `@router.message()` без фильтра — всегда последний (сейчас это
  пересылка в поддержку).

### Новая таблица или колонка (миграция)

1. Добавить `CREATE TABLE IF NOT EXISTS` в `db.init_db` — с комментарием,
   зачем таблица и какие у неё инварианты (в этом файле так принято).
2. Для **новой колонки в существующей** таблице — отдельный
   `try: ALTER TABLE … ADD COLUMN … except Exception: pass` в том же
   `init_db` (SQLite не умеет `IF NOT EXISTS` для колонок).
3. Индексы — сразу, если по колонке будут выборки.
4. Если в таблице есть `user_id`:
   - добавить `REFERENCES users(user_id) ON DELETE CASCADE`, если это
     возможно;
   - **иначе** дописать таблицу в `UserRepository.delete_user_completely`;
   - в обоих случаях расширить `tests/test_delete_user_completely.py`.
5. Решить, попадает ли таблица в `AnalyticsService.EXPORTABLE_TABLES`.
6. Обновить [data-model.md](data-model.md).

Обратная миграция не поддерживается: перед изменением схемы на проде
делайте `/backup`.

### Новый метод репозитория

- Докстринг: что возвращает, **берёт ли метод `db.lock`** (или требует,
  чтобы его взял вызывающий), идемпотентен ли.
- Read-modify-write → под локом. Простой инкремент с проверкой →
  атомарный `UPDATE … WHERE счётчик < лимит` + `rowcount` (так сделаны
  дневные капы лидерборда).
- Не импортируйте `services` на верхнем уровне `repository.py` — будет
  цикл; используйте ленивый импорт внутри метода (существующая практика).

### Новое событие аналитики

```python
await event_repo.log(user_id, "my_event", {"subject_id": sid, "value": v})
```

- Имя — `snake_case`, глагол в прошедшем времени (`*_completed`,
  `*_purchased`, `*_viewed`).
- `subject_id` / `mode` / `tip_id` в `properties` автоматически попадут в
  одноимённые колонки — называйте ключи именно так.
- Не кладите в `properties` пользовательский текст.
- Добавьте событие в таблицу в [analytics.md](analytics.md).

### Новая строка интерфейса

Никогда не пишите текст прямо в хендлере. См. [i18n.md](i18n.md):
ключ добавляется в `scripts/build_locales.py`, бандлы перегенерируются,
паритет ru/en проверяется `scripts/audit_i18n_keys.py` и
`tests/test_i18n.py`.

### Новый предмет или режим учёбы

1. Папка `study_materials/<subject_id>/` с контентом.
2. `subject_id` в `locale_bot.SUBJECT_IDS` и `bot.SUBJECTS`.
3. Ярлыки в `locales/ru.json` и `en.json` (`subjects.<id>`).
4. Ничего больше: меню строится data-driven — предмет появится сам, как
   только у него будет непустой контент.
5. Не готов к показу? `PREP_HIDDEN_SUBJECT_IDS` прячет из «Подготовки»,
   `PROFILE_COMING_SOON_SUBJECTS` — из блока прогресса.

Форматы файлов — [content-authoring.md](content-authoring.md).

### Новая админ-команда

1. Хендлер с `@router.message(Command("mycmd"))` и первой же строкой —
   проверкой `is_admin(...)` (для команд главного админа — сравнение с
   `MAIN_ADMIN_ID`).
2. Запись в `ADMIN_COMMANDS` (список для `/`-пикера).
3. Раздел в [../admin_commands.md](../admin_commands.md) с примером вывода.

### Новый фоновый цикл

- Живёт в `tasks.py`, внутри `while True` с `try/except` вокруг тела и
  `await asyncio.sleep(...)` в конце.
- Запускается в `main()` через `asyncio.create_task(..., name=...)` +
  `add_done_callback(_log_task_exception)` — иначе исключение до входа в
  цикл потеряется.
- Дедупликация обязательна: in-memory отметка «последняя дата/минута» +
  идемпотентность в БД.
- Вычисление «пора ли» выносится в чистую функцию (как
  `_compute_ended_week_iso`), чтобы тест не подменял системные часы.

## Стиль

- Комментарии и докстринги — по-русски (так во всём коде), идентификаторы —
  по-английски.
- Докстринг объясняет **почему**, а не пересказывает сигнатуру. В этом
  проекте принято фиксировать в докстринге принятые решения и отвергнутые
  альтернативы — это главный источник контекста при возврате к коду.
- Логи: `logger.info("тег.через.точки key=%s", value)` — ленивая
  интерполяция, без f-строк, без PII.
- Ошибки Telegram: сначала `TelegramForbiddenError` (INFO,
  `reason=blocked`), затем `TelegramBadRequest` (WARNING), затем общий
  `Exception` (WARNING/ERROR, `reason=<TypeName>`).
- Типизация в новых модулях, `from __future__ import annotations` там, где
  нужны современные аннотации.
- `bot.py` уже на 8 тысяч строк. Новую самостоятельную фичу лучше
  начинать отдельным модулем (как `plan_handlers.py`), регистрируя
  хендлеры из `main()`.

## Чеклист перед коммитом

1. `python -m pytest -q` — зелёный (802 теста).
2. `python scripts/check_docs.py` — документация сходится с кодом.
3. `python -m py_compile bot.py services.py repository.py db.py`.
4. `python -c "import bot"` — ловит ошибки в декораторах и на импорте.
5. Если трогали строки интерфейса — `python scripts/audit_i18n_keys.py`.
6. Новое поведение покрыто тестом; багфикс — регрессионным тестом.
7. **Документация обновлена в этом же коммите**:
   - изменилась схема → [data-model.md](data-model.md);
   - изменилась механика фичи → [features.md](features.md) и, если видно
     пользователю, [../README.md](../README.md) + [../user-flows.md](../user-flows.md);
   - новое событие → [analytics.md](analytics.md);
   - новая команда → [../admin_commands.md](../admin_commands.md);
   - изменился баланс лидерборда → [../LEADERBOARD.md](../LEADERBOARD.md)
     (спека — источник истины, правится **до** кода);
   - в шапке правленого документа обновлён `Doc sync`.
8. Запись в [../session_notes.md](../session_notes.md) — что сделано,
   что отложено.
9. Числа в документации (количество тестов, задач, таблиц) сверены с
   реальностью, а не скопированы из прошлой версии — за большинство из
   них теперь ручается `check_docs.py`.

## Частые ошибки

| Ошибка | Чем оборачивается |
|--------|-------------------|
| `datetime.now()` внутри новой формулы | Тест недетерминирован; см. [testing.md](testing.md) §1 |
| Захват `db.lock` внутри метода, который уже вызывается под локом | Дедлок |
| `await bot.send_message(...)` под `db.lock` | Лок держится на время сетевого вызова |
| Новая таблица с `user_id` без обновления `delete_user_completely` | Неполное удаление аккаунта, нарушение GDPR |
| Строка интерфейса мимо `t()` | Ломается английская локаль |
| Общий `@router.message()` выше специфичного | Специфичный хендлер никогда не сработает |
| Числа в README «на глаз» | Документация расходится с кодом — то, ради чего написан этот раздел |
