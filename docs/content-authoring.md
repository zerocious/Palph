# Наполнение контентом

> **Doc sync:** 2026-09-05.

Как добавить учебный материал, совет или арт питомца, ничего не трогая в
коде. Схема каталогов и требования спринт-плана — в
[../study_materials/README.md](../study_materials/README.md).

## Общее правило

Бот обнаруживает контент **по факту наличия файлов**. Предмет появляется в
меню, как только у него есть хотя бы один режим с непустым содержимым;
режим появляется, как только его файл перестал быть пустым. Ничего
регистрировать в коде не нужно и рестарт не требуется: и учебные
материалы, и советы читаются с диска при каждом обращении. Рестарт нужен
только после правки `locales/*.json` — бандлы локалей кешируются.

Директория: `study_materials/<subject_id>/`. Разрешённые `subject_id` —
`industrial-management`, `math`, `accounting`, `english`
(`locale_bot.SUBJECT_IDS`; расширяется по рецепту из
[development-guide.md](development-guide.md)).

## Флэш-карты — `flashcards.txt`

```
# Строки, начинающиеся с #, — комментарии
термин || определение
термин || определение || тема1, тема2
```

Одна карточка на строку. Хеш карточки — `md5(термин)[:8]`, поэтому
**правка термина создаёт новую карточку** и обнуляет прогресс по старой;
правка определения безопасна. Стартовое состояние SM-2: `EF = 2.5`,
`interval = 0`, `repetitions = 0`.

Третье поле (темы) читает только генератор спринт-плана; без него тема —
`general`.

## MCQ — `mcq.txt`

```
# Формат: вопрос || правильный ответ || неправ1 || неправ2 || неправ3
вопрос || верный || неверный || неверный || неверный
```

Варианты перетасовываются перед показом, вопросы в сессии тоже.
Хеш вопроса — `md5(вопрос)[:8]`. Рестарт бота не требуется.

## Ситуационные квизы — `situational/section-*.txt`

```
термин || определение || ключевое, слово, список || текст ситуации
```

Проверка ответа — по ключевым словам (`check_text_answer`), поэтому
третье поле важнее остальных: перечисляйте корневые слова, которые
обязаны прозвучать. Имя файла = id раздела (`section-i` … `section-iv`),
подписи разделов — в локалях (`quiz_sections.*`).

## Задачи — `tasks/task-NN.json`

Два вида: с картинкой и text-only.

```json
{
  "text_only": true,
  "problem": "Полный текст условия.",
  "accepted": ["8/27", "0.2963", "0,2963"],
  "solution_text": "Пошаговое решение, показывается после 2-й ошибки.",
  "hint": "Педагогическая подсказка, показывается после 1-й ошибки.",
  "group": "exam-task-1",
  "subtitle": "Пример 2",
  "topics": ["exam-task-1"]
}
```

| Поле | Обязательно | Заметки |
|------|:-----------:|---------|
| `text_only` | для текстовых | `true` — PNG не нужен |
| `problem` | для текстовых | Условие целиком |
| `accepted` | да | Все принимаемые формы ответа |
| `solution_text` | желательно | Альтернатива `task-NN-solution.png` |
| `hint` | нет | Показывается после **первой** ошибки |
| `group` | нет | Ссылка на `groups.json` |
| `subtitle`, `topics` | нет | UI и планировщик |

Сверка ответа (`task_answer_match.task_answer_matches`) сама понимает
дроби `a/b`, десятичные с точкой и запятой, целые и знак минуса, поэтому
`accepted` достаточно перечислить в основных формах. Для текстовых
ответов работает нормализованное сравнение (регистр и пунктуация не важны).

Награды: **3 🪙** за верный ответ с первой попытки, **2 🪙** со второй,
после второй ошибки — показ решения и 0 🪙.

### Группы задач — `groups.json`

```json
{
  "exam-task-1": {
    "title": "Билет — задача 1 (формула Бернулли)",
    "description": "Подсказка для автора, в UI не показывается"
  }
}
```

Если файл есть, перед сессией показывается инлайн-пикер групп с числом
задач в каждой.

### Порядок тем — `topics.json`

```json
{ "order": ["exam-task-1", "exam-task-2", "general"] }
```

Читается только генератором спринт-плана.

### Диагностика — `diagnostic/default.json`

Входной тест для спринт-плана; `ref` должен совпадать с хешами каталога
(MD5-префикс для MCQ и ситуационных, `task-NN` для задач). Формат — в
[../study_materials/README.md](../study_materials/README.md).
Для генерации плана нужно **≥ 10** элементов каталога и непустая
диагностика.

## Советы по продуктивности — `tips/`

| Файл | Категория |
|------|-----------|
| `time-management.json` | ⏰ Тайм-менеджмент (`tm`) |
| `memory.json` | 🧠 Техники запоминания (`mem`) |
| `bot-guide.json` | 🎯 Как пользоваться ботом (`bot`) |
| `links.json` | 🔗 Внешние материалы (кнопки-ссылки) |

```json
{
  "category": "tm",
  "tips": [
    {
      "id": "tm-01",
      "title": "Правило двух минут",
      "emoji": "⏳",
      "body": "Если дело занимает меньше двух минут — сделай сразу.",
      "tags": ["study"],
      "action": "Выбери одну задачу на сегодня и запиши её в заметки."
    }
  ]
}
```

- `id` должен начинаться с префикса категории (`tm-`, `mem-`, `bot-`) —
  по нему определяется категория при показе.
- `tags` управляют контекстным подбором: `timer` (во время таймера),
  `study` / `focus` / `timer` / `bot` (если сегодня ещё не учился),
  `flashcards` (если есть карточки к повторению).
- Совет без `title` или `body` тихо отбрасывается при загрузке.
- Переводы: файл с тем же именем в `tips/<locale>/`; при отсутствии
  берётся корневой.
- **Кеша нет:** `locale_bot.tip_categories()` перечитывает JSON на каждый
  вызов, поэтому правка файла видна без рестарта. (Модульная константа
  `bot.TIP_CATEGORIES` — снимок RU-каталога на момент импорта, её
  используют только тесты.)
- Валидация: `tests/test_tips_content.py`, `tests/test_productivity_tips_files.py`.

## Арт питомца — `assets/pet/`

Имя файла кодирует состояние:

```
assets/pet/<emotion>_<color>_<accessory>.png     # плоский legacy-набор
assets/pet/<period>/<emotion>_<color>_<accessory>.png   # суточные варианты
assets/pet/<period>/default.png
assets/pet/<emotion>.gif                          # анимация (sad.gif и т.д.)
```

- `emotion` ∈ `neutral`, `joy`, `sad` (старые имена `happy`, `excited`,
  `sleepy`, `studying` поддерживаются как фолбэк).
- `color` ∈ `orange`, `grey`, `blue`, `green`, `pink`.
- `accessory` ∈ `none`, `hat`, `glasses`, `scarf`, `crown`.
- `period` ∈ `morning`, `day`, `evening`, `night`.

Файла может не быть: `render_pet` идёт по цепочке фолбэков вплоть до
`default.png` (см. [features.md](features.md) §5), поэтому набор можно
пополнять постепенно.

> **Пока включён `services.PET_SINGLE_IMAGE_MODE = True`**, бот показывает
> только `assets/pet/<period>/default.png` — новые файлы с эмоциями,
> цветами и аксессуарами лежат «про запас» и начнут использоваться после
> переключения флага. См. [features.md](features.md) §5.

**Что лежит сейчас:** в каждой из четырёх папок периода — по четыре файла
(`default.png`, `neutral_orange_none.png`, `joy_orange_none.png`,
`sad_orange_none.png`), это настоящий пользовательский арт. В плоской
`assets/pet/` — 176 PNG и 7 GIF, оставшиеся от прежнего набора из пяти
эмоций; они работают как legacy-фолбэк (`happy`/`excited` → `joy`,
`sleepy`/`studying` → `neutral`). Любая комбинация «цвет + аксессуар»
поверх суточного арта сейчас разрешается в `<period>/<emotion>_orange_none.png`,
пока не появятся соответствующие файлы.

Плейсхолдеры генерируются один раз:

```bash
python scripts/build_pet_assets.py                  # 75 PNG + 3 GIF
python scripts/build_pet_assets.py --with-periods   # + копии по периодам
```

Настоящий арт просто кладётся поверх — код не меняется.
