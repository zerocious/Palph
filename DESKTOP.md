**Статус:** design draft, решения не приняты. Документ — развилка: три

## 1. Зачем вообще десктоп

Бот в Telegram хорош для «напомнить и зачесть», но у него нет доступа к
экрану, на котором студент реально учится. Всё, что ниже, — вещи,
**невозможные** в Telegram, а не «то же самое, только в окне»:

| Возможность | Почему только десктоп |
|---|---|
| 🐾 **Питомец на рабочем столе** | Прозрачное always-on-top окно (Shimeji-style): питомец сидит в углу экрана, реагирует на таймер, грустнеет при простое. Ассеты **уже есть** — эмоции × цвет × аксессуар × время суток |
| ⏱ **Таймер как виджет** | Мини-окно поверх всех окон + иконка в трее + прогресс на таскбаре. Не надо переключаться в Telegram, чтобы узнать «сколько осталось» |
| 🔔 **Нативные тосты Windows** | Утреннее/вечернее напоминание приходит в центр уведомлений, а не в чат, который замьючен |
| 🎯 **Focus mode** | Трекинг активного окна во время сессии: «12 из 25 минут ты был в Chrome». Опционально — блокировка отвлекающих сайтов/приложений на время помидора |
| 📊 **Дашборды** | `AnalyticsService` уже отдаёт structured data (не строки) — графики рисуются напрямую, без ASCII-таблиц в чате |
| 🃏 **Флэш-карты с клавиатуры** | `Space` — перевернуть, `1/2/3` — оценить. SM-2 сессия на 40 карточек в чате — боль, в окне — 3 минуты |
| 🚀 **Автозапуск с Windows** | Приложение стартует в трее, стрик не теряется потому что «забыл открыть Telegram» |

Всё остальное (квизы, MCQ, задачи, магазин питомца, лидерборд, друзья)
десктоп дублирует ради полноты, но ценность там ниже.

## 2. Что уже готово к переиспользованию

Проверено по коду:

```
bot.py (8057 строк, aiogram)  ─┐
plan_handlers.py (791)         ├─→ services.py (2858) ─→ repository.py (2373) ─→ SQLite
tasks.py (планировщик, 147)   ─┘        ↑                      ↑
                                  единственная                чистый aiosqlite,
                                  связь с aiogram —           ноль зависимостей
                                  импорт exceptions           от фреймворка
```

- **`repository.py`** — 15 репозиториев (`UserRepository`, `PetRepository`,
  `LeaderboardRepository`, `FriendRepository`, `PlanRepository`, …),
  конструктор принимает `aiosqlite.Connection`. UI-агностичен на 100%.
- **`services.py`** — сервисы принимают репозитории + **опциональный**
  `bot=None` (см. `StudyService.__init__`), т.е. уже умеют работать без
  Telegram: без `bot` просто пропускается отправка уведомлений.
- **Чистые функции**, которые десктоп может переиспользовать буквально:
  `sm2_update`, `derive_emotion`, `get_pet_time_period`, `render_pet`,
  `streak_multiplier`, `freeze_cost`, `piecewise_time_pts`,
  `user_calendar_keys`.
- **`i18n.py` + `locales/{ru,en}.json`** — 34 неймспейса строк, ru/en.
  Десктоп берёт те же файлы, интерфейс сразу двуязычный.
- **`assets/pet/`** — ~500 PNG (эмоция × цвет × аксессуар) + подпапки
  `day/evening/…` для времени суток + GIF. Готовый арт для десктоп-питомца.
- **`study_materials/`** — 102 JSON-файла контента (math, english,
  accounting, industrial-management).
- **732+ теста** на домене — рефакторить его страшно, **и не нужно**.

Вывод: писать надо **только UI-слой + транспорт**. Домен не трогаем.

## 3. Развилка №1 — где живут данные

Это главный выбор, он определяет всё остальное.

### Вариант A. Тонкий клиент поверх HTTP API (рекомендуется)

К боту добавляется `api.py` — aiohttp-сервер в том же процессе (aiohttp
**уже транзитивная зависимость aiogram**, новых пакетов ноль). Он поднимает
те же репозитории на том же соединении с БД. Десктоп ходит по HTTPS.

```
                         ┌── bot.py ─────────── Telegram
services.py + repository.py ─┤
   (общее ядро, не меняется)  └── api.py (aiohttp) ── HTTPS ── Palph Desktop (.exe)
                                       ↑
                              тот же SQLite, одна правда
```

- ✅ Одна правда о данных: монеты/стрик/SM-2 не разъезжаются
- ✅ Работает на нескольких ПК + телефон одновременно
- ✅ Бот продолжает слать напоминания, когда ПК выключен
- ✅ Тот же API потом обслужит Telegram Mini App и Android
- ⚠️ Нужен публичный HTTPS-эндпоинт — **вопрос к bothost.ru**, отдаёт ли
  тариф порт/домен. Если нет: вынести API на Fly.io/Railway рядом с той же
  БД, либо переехать на VPS
- ⚠️ Нужна аутентификация устройств (см. развилку №3) и rate-limiting
  (`UserRateLimiter` уже есть, переиспользуется)
- ⚠️ Без сети приложение — витрина. Лечится офлайн-очередью в фазе 5

**Оценка:** API-слой ~600–900 строк на первые фазы.

### Вариант B. Local-first + синхронизация

Десктоп держит свою SQLite (та же схема из `db.py`), пишет локально,
синкает дельты с сервером.

- ✅ Полностью работает офлайн
- ❌ Конфликты на монетах, стрике и SM-2-интервалах — реально сложная
  задача (нужны CRDT либо server-authoritative replay событий)
- ❌ Двойная точка отказа и вдвое больше тестов

**Вердикт:** не для v1. Но у вас **уже есть таблица `events`** —
приземлённый компромисс: локальная очередь событий, сервер их проигрывает
и остаётся авторитетным. Это фаза 5, а не фундамент.

### Вариант C. Автономное приложение без связи с ботом

Своя БД, свой прогресс, бот отдельно.

- ✅ Делается быстрее всего, никакого хостинга
- ❌ Два параллельных прогресса в геймифицированном приложении про
  привычки — это убивает саму механику (стрик в боте 40 дней, в
  приложении 3)

**Вердикт:** нет.

> **Рекомендация: A.** Офлайн-очередь из B добирается позже как фаза 5.

## 4. Развилка №2 — стек UI

| Стек | Язык | Установщик | Питомец на десктопе | Риск для команды |
|---|---|---|---|---|
| **PySide6 (Qt6) + QML** | Python | ~90–130 МБ (PyInstaller) | Тривиально: `Qt.WA_TranslucentBackground` + `FramelessWindowHint` | **Низкий** — тот же язык, что и весь проект |
| Tauri 2 + React/TS | Rust + TS | ~10 МБ | Да, но оконная магия на Rust | Высокий: два новых языка |
| Electron + React | JS | ~150 МБ, ~200 МБ RAM | Да | Средний: новый язык, тяжёлый рантайм |
| .NET 8 WinUI 3 | C# | ~60 МБ | Да, самый нативный вид | Высокий: новый язык, только Windows |
| Telegram Mini App + обёртка | HTML/JS | зависит от обёртки | Нет без нативного шелла | Средний |

**Рекомендация: PySide6 + QML.**

Почему именно он для *этого* проекта:

1. Проект — 16 290 строк Python. Второй язык удвоит стоимость поддержки.
2. Чистые функции домена (`sm2_update`, `derive_emotion`, `render_pet`)
   импортируются в приложение **как есть**, без портирования на TS/C#.
   Одна логика — один набор багов.
3. Прозрачное always-on-top окно для питомца в Qt — 5 строк. В Electron —
   борьба с click-through, в Tauri — Rust-код под каждую платформу.
4. `QSystemTrayIcon`, нативные тосты, глобальные хоткеи, автозапуск — из
   коробки.
5. LGPL — можно распространять закрыто (в отличие от PyQt6/GPL).
6. Кроссплатформенность бесплатно: тот же код даст .app и .AppImage,
   если понадобится.

Минус честно: размер установщика и то, что QML-вёрстка «не React» — но
приложение на 6–8 экранов это переживает.

**Отдельно про Mini App.** Если цель — *одна* вёрстка на Telegram и
десктоп, то путь другой: пишем web-UI, отдаём его и как Telegram Mini App,
и внутри Tauri-обёртки. Максимальный рычаг, но требует фронтенд-стека и
всё равно нативного шелла для питомца/трея. **Это не отменяет вариант A** —
API один и тот же, так что решение можно отложить, не заблокировав фазу 1.

## 5. Развилка №3 — как связать приложение с аккаунтом

Логина/пароля в проекте нет и заводить не надо — личность даёт Telegram.

**Схема pairing по одноразовому коду (рекомендуется):**

1. В приложении: «Подключить аккаунт» → показывается deep-link
   `t.me/<bot>?start=pair_<nonce>` + QR.
2. Пользователь открывает бота, бот проверяет `nonce`, показывает
   «Подключить этот ПК к аккаунту?» с кнопкой подтверждения.
3. После подтверждения бот записывает связку и приложение (опрашивая
   `/pair/poll`) получает долгоживущий **device token**.
4. Токен лежит в **Windows Credential Manager** (через `keyring`), не в
   `.ini` рядом с exe.

Прецедент в кодовой базе уже есть — таблица `friend_invite_tokens` и
`/share_friend` делают ровно этот трюк с deep-link'ами, так что схема
ложится на знакомый код.

Новые таблицы (миграция в `db.py`):

```sql
CREATE TABLE IF NOT EXISTS devices (
    device_id     TEXT PRIMARY KEY,      -- uuid4, генерит приложение
    user_id       INTEGER NOT NULL,
    token_hash    TEXT NOT NULL,         -- sha256, plaintext не храним
    device_name   TEXT,                  -- имя ПК, чтобы отзывать осознанно
    created_at    TEXT NOT NULL,
    last_seen_at  TEXT,
    revoked_at    TEXT
);

CREATE TABLE IF NOT EXISTS pair_codes (
    nonce      TEXT PRIMARY KEY,
    device_id  TEXT NOT NULL,
    user_id    INTEGER,                  -- NULL пока не подтверждено
    created_at TEXT NOT NULL,
    expires_at TEXT NOT NULL,            -- TTL 10 минут
    used_at    TEXT
);
```

Плюс экран «Мои устройства» в профиле бота с кнопкой «Отозвать».

## 6. Черновик API-контракта

`/api/v1`, Bearer device token, JSON. Эндпоинты ложатся 1:1 на
существующие репозитории — новой бизнес-логики почти нет.

```
POST   /pair/start            {device_id, device_name} → {nonce, deep_link, expires_at}
GET    /pair/poll?nonce=      → 202 pending | 200 {token, user_id}
POST   /devices/revoke        {device_id}

GET    /me                    → профиль, монеты, уровень, стрик, локаль
GET    /pet                   → эмоция, цвет, аксессуар, имя, XP, url ассета
POST   /pet/customize         {color, accessory}  (PetRepository)
GET    /pet/catalog           → каталоги цветов/аксессуаров + цены + уровни

POST   /sessions/start        {duration_min} → {session_id}
POST   /sessions/finish       {session_id, actual_min, rating} → монеты, ачивки, level-up
POST   /sessions/abort        {session_id}

GET    /flashcards/due?subject=      → очередь SM-2 на сегодня
POST   /flashcards/{id}/review       {quality} → следующий интервал
GET    /subjects                     → предметы + доступные режимы
GET    /mcq?subject= | /tasks?subject=
POST   /mcq/{id}/answer | /tasks/{id}/answer

GET    /stats/summary?period=        → для дашбордов
GET    /leaderboard?segment=         → weekly, уже посчитан LeaderboardService
GET    /friends
GET    /reminders                    → времена утро/вечер + флаг «десктоп онлайн»
WS     /events                       → push: напоминание, level-up, заявка в друзья
```

**Важное правило (двойные уведомления):** `devices.last_seen_at` служит
presence-флагом. Если ПК онлайн — напоминание уходит нативным тостом, а
`ReminderService` пропускает Telegram-сообщение (или наоборот, по
настройке пользователя). Иначе каждое напоминание придёт дважды.

## 8. Раскладка репозитория и сборка

Монорепо, бот не переезжает:

```
Palph/
├── bot.py, services.py, repository.py, db.py   # без изменений
├── api.py                                       # новое: aiohttp-слой
├── desktop/
│   ├── palph_desktop/
│   │   ├── app.py            # точка входа, QApplication, трей
│   │   ├── api_client.py     # httpx-клиент + хранение токена (keyring)
│   │   ├── pet_window.py     # прозрачное always-on-top окно
│   │   ├── timer.py          # помидор + виджет
│   │   ├── ui/*.qml          # экраны
│   │   └── resources/        # locales/*.json + assets/pet (симлинк/копия при сборке)
│   ├── requirements.txt      # PySide6, httpx, keyring, plyer
│   ├── palph.spec            # PyInstaller
│   ├── installer.iss         # Inno Setup → Palph-Setup-x.y.z.exe
│   └── tests/
└── tests/                    # существующие 732+, не трогаем
```

- Сборка: PyInstaller (`--onedir`, быстрее старт, чем `--onefile`) →
  Inno Setup → один установщик с ярлыком и опцией автозапуска.
- CI: отдельный GitHub Actions job на `windows-latest`, артефакт —
  установщик; релизы через GitHub Releases (там же канал автообновления
  для фазы 5).
- Подпись кода: без сертификата Windows SmartScreen будет ругаться на
  каждой установке. EV-сертификат ~$200–400/год — **решить, платим или
  живём с предупреждением** (для учебного проекта второе нормально).

## 9. Риски и открытые вопросы

1. **Хостинг API.** Отдаёт ли тариф bothost.ru публичный HTTP-порт и
   домен? Если нет — куда выносим API, и как он тогда ходит в ту же БД?
   Это блокер фазы 1, проверить первым.
2. **SQLite при двух писателях.** WAL уже включён, и если `api.py` живёт
   в том же процессе, что бот, — проблемы нет. Если API выносится
   отдельным процессом/хостом, нужен либо один владелец БД, либо переезд
   на Postgres. Ещё один аргумент за «API внутри процесса бота».
3. **Двойные уведомления** — решается presence-флагом (см. §6), но
   правило надо зафиксировать в спеке до фазы 2.
4. **Размер ассетов.** `assets/pet/default.png` — 2 МБ, всего ~500 PNG.
   Для установщика их надо прогнать через `scripts/build_pet_assets.py` и
   ужать, иначе дистрибутив распухнет.
5. **Приватность.** Трекинг активного окна (фаза 5) — это сбор
   чувствительных данных. Строго opt-in, только локально, и обязательный
   апдейт [PRIVACY.md](PRIVACY.md) / [PRIVACY.ru.md](PRIVACY.ru.md).
6. **Кто носитель правды по времени.** Стрики и weekly rollover
   UTC-якорные (см. LEADERBOARD.md). Десктоп **не** считает даты сам —
   только показывает то, что вернул сервер, иначе поедет часовой пояс.
7. **Тесты.** Домен покрыт, API-слой и клиент — нет. Заводим
   `tests/test_api_*.py` (aiohttp test utils) и `desktop/tests/` сразу,
   а не «потом».
